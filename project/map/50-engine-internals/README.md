# Engine internals

_The dispatcher and the TypeScript modules every built-in verb uses._

This subtree covers the shared substrate for the project's final quality check (the Gate), the worktree workflow, and shared guidance. [`dispatch.ts`](../../../src/engine/dispatch.ts) is the **dispatcher**: it finds the project root (the nearest ancestor with a `discern.toml`), routes a known `discern <verb>` to its built-in binary handler, and routes requests in the explicit Project Script namespace. The root-aware core in [`project_scripts.ts`](../../../src/engine/project_scripts.ts) discovers the executable files under a checkout's `[scripts].dir`. `discern scripts <name>` executes one with its argument tail and the `DISCERN_*` environment. The Desk uses the same core for a selected worktree.

A word outside the closed root vocabulary reports `unknown command "<word>"` and gives the next action. The dispatcher checks the cross-tool synonym table in [`shared/vocabulary.ts`](../../../src/shared/vocabulary.ts) first: "init" and "install" name `setup`, "check" names `prepare`, "sync" names `update`, and "land" and "merge" name `accept`. Under [ADR 0120](../_adr/0120-launch-verb-canon.md)'s forgiveness policy, the table supplies suggestions while dispatch remains on the canonical names. The near-match suggester then checks built-ins and namespaced project script names. Every refusal points to `discern docs` for the manual and `discern --help` for the command list. Under `--json`, the refusal uses the uniform result envelope with error `unknown_command` and puts the actions in `hints`. The refusal still renders outside a project or with an unreadable config, where a newcomer's first guess often lands.

`KNOWN_VERBS`, defined in [`shared/verbs.ts`](../../../src/shared/verbs.ts), is the set of installer and engine names. It drives routing, grammatical normalization, help coverage, Logbook begin-event enrollment, and the test that proves every built-in name remains legal inside the Project Script namespace. Every subsystem's verbs are registered because dispatch has no toggle layer ([ADR 0101](../_adr/0101-retire-the-features-toggles.md)). A verb can stay out of the help listing and continue dispatching, as `preset` does while no presets ship and `setup` does once bootstrapped. The router in [`main.ts`](../../../src/main.ts) resolves the verb as the first token outside the global flags. This gives `discern --json <verb>` and `discern <verb> --json` the same route, including the pre-setup redirect ([ADR 0036](../_adr/0036-unify-setup.md)), welcome/help split, and Project Script dispatch. The root help renders in full and exits 0 with a broken, missing, or schema-invalid `discern.toml`, preserving the recovery route when config cannot load.

The stack-neutral logic behind the built-in verbs (the Engine) is TypeScript compiled into the binary under [`src/engine/`](../../../src/engine/). It shares [`src/shared/`](../../../src/shared/) with the installer verbs. A project needs neither Deno nor Node to run discern. Directories group the built-in handlers by area: the Gate and job runner ([`gate/`](../../../src/engine/gate/), [`jobs/`](../../../src/engine/jobs/)), scope classification ([`scopes/`](../../../src/engine/scopes/)), worktree lifecycle and identity ([`worktree/`](../../../src/engine/worktree/)), and the guidance compiler ([`guidelines.ts`](../../../src/engine/guidelines.ts)). The compiler assembles discern's built-in guidance with the project's sources and materializes the Skills. Shared concerns live under [`src/shared/`](../../../src/shared/): config reading, the [paths registry](../../../src/shared/paths_registry.ts), known-job and stage constants, the Portable Operating System Interface (POSIX) `cksum` port, and root discovery with `DISCERN_*`.

The command-line interface (CLI) pins `@discern-sh/design-system@0.14.0` and uses its root, `./cli`, and `./cli/interactive` graphs. Tests traverse each public closure, match its immutable JSR origin and resolved version to the lock, and exclude React and sibling-checkout paths from the CLI graphs.

[`src/lib/terminal.ts`](../../../src/lib/terminal.ts) is the process boundary for package rendering ([ADR 0279](../_adr/0279-external-terminal-rendering-crosses-one-process-boundary.md)). It snapshots output policy, attachment, environment, dimensions, theme, and Token roles. Character repertoire, styling, and cursor control remain independent: UTF-8 `TERM=dumb` keeps Unicode in static output. Safe-text adapters make product facts inert; raw child bytes bypass them.

Generic display measurement, ANSI stripping, truncation, padding, and wrapping delegate to public package functions through [`src/lib/text.ts`](../../../src/lib/text.ts). The local façade retains hanging indents, the explicit long-token overflow policy, content-shaped reports, terminal-size conveniences, sparklines, and meter projection. `TerminalContext` exposes package Token roles, so feature renderers do not import low-level ANSI or theme helpers around the process boundary. `Logger` and `Out` own channels, groups, and effects; they are not palette authorities. Both are stream configurations of the narration authority in [`src/lib/narration.ts`](../../../src/lib/narration.ts), whose sink owns every blank-line boundary; [Emitting output from a new verb](emitting-output.md) shows the blessed patterns. Every human frame managed by discern crosses single-line or multi-line safe text before Components or styling. Raw/exported documents, JSON, HTML, MCP, and project child bytes remain outside that edge.

[`src/lib/terminal_interaction.ts`](../../../src/lib/terminal_interaction.ts) is the sole product interaction choke point. It maps discern's admission, validation, values, stable searchable defaults, and semantic groups into public package requests; first-class package heading entries keep every populated group visible without selectable sentinels. Search defaults cross as stable IDs and fail before interaction when no choice owns the product value. [`tests/fixtures/interactive_tty_harness.ts`](../../../tests/fixtures/interactive_tty_harness.ts) drives that production path, including height-responsive frames and repeated short-terminal cycles. The docs browse loop retains its own highlighted document between iterations without persisting it across commands. The later Desk programme owns a separate full-application real-terminal journey rather than treating this generic interaction proof as Desk-loop coverage.

The Git-derived [`terminal_boundary_guard_test.ts`](../../../tests/terminal_boundary_guard_test.ts) outlaws direct presentation dependencies and imports, request/painter bypasses, feature-local process policy, duplicate generic text/triangle/palette authorities, raw control literals, and statically provable unsafe Component props. It reserves prompt vocabulary in the terminal interaction authority for coding-agent instructions. `@cliffy/command` remains the sole direct Cliffy alias/root/import and the parser/help fact source. Its package-owned transitive graph includes `@cliffy/table`; the guard derives that closure from `deno.lock` and rejects any independently rooted Cliffy presentation package.

Terminal art has 3 registry-backed projections. The product owns variants of canonical `◮ discern` and 2 compositions: the solid pyramid and recursive gasket. The package owns all 4 Unicode and ASCII glyphs, weave and spinner orders, plus the reusable pattern, progress, section-rule, workflow-stepper, and activity-beacon renderers. The motif registry adapts those public APIs; the product registry derives package constants. Every entry supplies a static renderer and ANSI-free timeline whose final frame equals its static output.

Package `InlineFramePainter` rejects frames it cannot wholly replace. Gate and art callers stop repainting and print one static completion. An injected viewport update can trigger the same refusal; live resize observation remains outside the snapshot. A failed write triggers no speculative cursor cleanup. Motion stays off for non-TTY, CI, `TERM=dumb`, plain, or constrained output. Package Components present setup, help, docs, and Doctor without changing parser facts or structured results ([ADR 0066](../_adr/0066-grouped-cli-help.md), [ADR 0088](../_adr/0088-fresh-setup-welcome-decorates-only-on-tty.md), [ADR 0279](../_adr/0279-external-terminal-rendering-crosses-one-process-boundary.md)).

[`scopes/glob.ts`](../../../src/engine/scopes/glob.ts) matches scope globs in memory, so a glob in a config value does not expand against the filesystem the way an unquoted shell glob would. A Project Script is an executable with normal shell globbing. Built-in verbs are the normal consumers of this internal boundary.

Every **effectful** verb follows a **plan/apply** shape ([ADR 0027](../_adr/0027-plan-apply-engine-execution.md)). It computes a pure, read-only plan by loading config, classifying changed scopes, and reading the resource ledger. A thin executor then applies the plan. This split gives `done`, `accept`, `worktree` setup/teardown/prune, and `standards` a `--dry-run` that renders the plan without touching anything. Their `--json` form serializes the `DiscernResult` returned by every verb instead of deriving it again ([ADR 0028](../_adr/0028-result-envelope-and-diagnostics.md)).

The plan vocabulary, diagnostic, envelope, and shared result renderers live in [`shared/result.ts`](../../../src/shared/result.ts), the base layer both halves import. Terminal, JSON, Markdown, and MCP presentations project that envelope at their delivery boundaries. The `Out` and `Logger` sink adapters sit beside the writers they bridge, generalizing the installer's [`fs_plan.ts`](../../../src/lib/fs_plan.ts) and [`plan_view.ts`](../../../src/lib/plan_view.ts). Pure functions hold the decision logic each verb plans from, including Gate job derivation, scope-gate selection, and the prune garbage-collection reclaim decision. Unit tests exercise those functions without a subprocess.
