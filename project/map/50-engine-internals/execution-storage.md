# Source execution and recovery storage

The execution adapter distinguishes source validation, a release observation, and a recovery capture. Start with [the workspace adapter](../../../src/engine/execution/workspace.ts) when deciding which observation an effect needs.

Source validation retains checkout exclusion, Git attachment and index semantics, resource ownership, and the producer's exact input evidence. It does not install another revision or copy ignored files. Both source observation and recovery require the checkout’s native Git index. Linked source worktrees require matching ready ownership for configured worktree resources. The main checkout has no per-worktree resource enrollment. A source observation cannot authorize restoration or checkout disposal.

A release observation hashes local files without storing their bytes. Its semantic subject excludes only raw index cache bytes. A recovery capture stores exact index bytes, working files, link text, and staged binary patches. Manifest and release subjects share native semantics; older exact-byte subjects retain their narrower matching rules. Unsupported indexes and nested repository preservation refuse destructive recovery and retain the checkout.

[Payload storage](../../../src/engine/execution/payloads.ts) streams regular files through a fixed buffer into private staging, then publishes an immutable digest coordinate. Unchanged payloads share one stored file across snapshots and attempts. Ignored status supplies no regeneration authority. Interrupted or changing observations cannot authorize cleanup.

[The storage lifetime](../../../src/engine/execution/storage_lifetime.ts) permits concurrent writers and reference inventory. Only deletion needs exclusive access after writers finish. Hold it from observation through publication of its durable references when adding a new execution consumer. The native executor already supplies this lifetime. Keep expensive observation, hashing, copying and file sync outside the common publication boundary; recheck checkout ownership and record revisions before publication.

[Reclamation](../../../src/engine/execution/reclamation.ts) reads current and historical completion records and the full artifact graph. Active attempts and current return records retain their manifests. Historical landing, convergence, and retirement references remain roots even after their owning record advances. Shared payloads survive while any retained node refers to them. Unknown versions, malformed references, incomplete inventories, and changed observations refuse deletion. Call `reclaimExecutionStorage` only after the relevant environment has retired; retirement integration owns that decision.

The native executor publishes each required capture into environment revision history before destructive effects. Legacy attempts without those edges remain protected. [The publication witness](../../../src/engine/completion/publication_witness.ts) changes before record, manifest or reclamation mutations. Reclamation checks it after inventory and again under the common lock before a bounded parent-first deletion batch. Required distinct bytes can grow storage; this contract bounds buffers, documents and deletion work while eliminating duplicate payloads ([ADR 0386](../_adr/0386-retain-recovery-bytes-through-durable-reference-graphs.md)).
