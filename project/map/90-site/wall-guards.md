# The wall's guards

Part of [the homepage wall](the-homepage-wall.md), which names the files and tests this page refers to.

- [`tests/site_wall_island_test.ts`](../../../tests/site_wall_island_test.ts) holds the island boundary. Only `island.tsx` imports `react-dom/client`, and no module imports the island. The served wall equals the component's render. The island reads back the props the server wrote, link labels included, and each label is the title of the page it names. The built bundle is fresh and named by its digest. `wallIslandFile` refuses a bundle that is not the island, and no other module under `site/` spells the island's name. A file gets the immutable cache policy when its name carries the digest of its bytes, and no other file gets it. The island loads on `/`, and no other live route loads a script that contains a React runtime. The test finds a runtime by script content, through imports, under any file name. The same file holds [the custom-property and attribute contract](wall-motion.md#knobs-and-the-tuning-panel) in both directions and [the far-view rules](wall-motion.md#keyboard-focus-and-the-far-view).
- [`tests/site_design_system_runtime_test.ts`](../../../tests/site_design_system_runtime_test.ts) keeps the island out of the production server's module graph and applies the same content check to every bundle route. It takes the check, `carriesReactRuntime`, from `assets.ts`, where the build uses it too.
- [`tests/site_homepage_browser_test.ts`](../../../tests/site_homepage_browser_test.ts) loads the page in a real browser at phone and laptop sizes, under the production Content Security Policy. Its cases cover the page without script, hydration with the stage and the lens, hydration under development React, reduced motion, the keyboard's walk, narrow and zoomed rooms, the chip row, more contrast, touch, and the tuning panel. Every case fails on a page error, a console error or warning, a failed request, or an error response.
- [`tests/site_wall_sheet_browser_test.ts`](../../../tests/site_wall_sheet_browser_test.ts) holds [the opened card](wall-opened-card.md) in a real browser, with the same fault capture: every way out, hurried input, a refused transition, the mark's crossing, a resize, print, touch sizes, and a short screen. It also holds a pointer's press on [a wall the keyboard has laid flat](wall-motion.md#keyboard-focus-and-the-far-view).
- [`tests/site_theme_test.ts`](../../../tests/site_theme_test.ts) and [`tests/site_homepage_theme_browser_test.ts`](../../../tests/site_homepage_theme_browser_test.ts) hold [the page's fixed dark theme](design-system-consumption.md#build-and-theme): the server's markup for every live route, the painted page on a light device with and without script, the stored choice left as it was, and dark ink for every word on paper.
- [`tests/site_wall_card_test.ts`](../../../tests/site_wall_card_test.ts) holds [a card's](wall-deck-cards-and-glyphs.md#cards) markup, type, surfaces, and states, and the rule that no wall stylesheet blurs a backdrop or fixes a background to the viewport.
- [`tests/site_wall_interactions_test.ts`](../../../tests/site_wall_interactions_test.ts) holds [the lens](wall-lens.md), the receded card's contrast, and [how a card opens](wall-opened-card.md).
- [`tests/site_wall_light_test.ts`](../../../tests/site_wall_light_test.ts) holds [the pointer light](wall-pointer-light.md): its arithmetic, the non-inheriting properties, the restyle budget for pointer travel and for the keyboard, the trace of forced layout, the moved wall, the selection colors, and the forced-colors and print fallbacks.
- [`tests/site_wall_deck_test.ts`](../../../tests/site_wall_deck_test.ts) resolves every citation and holds [the copy rules](wall-deck-cards-and-glyphs.md#the-deck). It ties each numeral to its inventory, requires the wall and every lens to open on the lead, and requires neighbors on the wall to span several clusters.
- [`tests/site_wall_glyph_test.ts`](../../../tests/site_wall_glyph_test.ts) holds [the glyphs](wall-deck-cards-and-glyphs.md#glyphs): the vocabulary, the triangle budget, exact arithmetic, the two drawings, the pose and its ease, the paint order, the dashed stroke, and the evenness of the set. [`tests/site_wall_glyph_motion_test.ts`](../../../tests/site_wall_glyph_motion_test.ts) holds the move's cost in a real browser.
- [`tests/site_prose_test.ts`](../../../tests/site_prose_test.ts) requires the homepage's prose projection to hold every card's second paragraph and the words each lens shows.
- [`tests/site_ui_test.ts`](../../../tests/site_ui_test.ts) applies the shared component boundary to `site/wall`: no `dangerouslySetInnerHTML`, and no design-system class name written by hand.
- [`tests/site_accessibility_test.ts`](../../../tests/site_accessibility_test.ts) and [`tests/site_homepage_scaffold_test.ts`](../../../tests/site_homepage_scaffold_test.ts) audit the homepage's landmarks, its manual link, and its accessibility findings.

Helper modules serve these tests, and a new wall test starts from them:

- [`tests/wall_stylesheets.ts`](../../../tests/wall_stylesheets.ts) reads the wall's stylesheets for every test. Its parser keeps each rule's at-rule context and splits a selector list or a value only outside brackets. Every test that holds a stylesheet to a rule reads it through that parser, so they agree on what a rule is. The module also owns `MOTION_PROPERTY`, the shared expression for a property that moves a box or times a change.
- [`tests/site_wall_browser.ts`](../../../tests/site_wall_browser.ts) holds what the real-browser tests share: the production handler behind a page that records every fault, the viewports, and the selectors for the near and far wall, which it builds from the exported attribute names. Its `motionSettled` waits only for finite animations on the document's own timeline. The lens bar's scroll-driven animations never end, so a wait for every animation would never return.
