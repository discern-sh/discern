# Testing

_How this repository's tests are written, how they run, and which patterns the gate requires._

The project's final quality check (the gate) runs the `test` job from `discern.toml`. This page explains how to write tests that pass it and how to run them while iterating. GitHub Actions runs the full gate on Ubuntu for every pull request and push to `main`. The native Apple-silicon lane joins those events when the repository is public. While it is private, the Apple-silicon release row runs the same gate before compiling. A newer commit on the same Git reference cancels an in-progress remote gate because its result would describe an obsolete tree.

## How tests run

The suite is plain `deno test`, wired as the `test` job:

```sh
deno task test                                   # full suite (what the Gate runs)
deno task test tests/upgrade_migrations_test.ts  # a single file while iterating
deno task test --filter "convergence"            # a filtered subset by test name
```

`deno task test` enters the fleet cap through `discern queue`, then [`scripts/run_tests.ts`](../../../scripts/run_tests.ts) opens and closes a temporary `127.0.0.1` listener before starting Deno. The local network probe exercises the same capability as the suite's process-interruption and site journeys; a sandbox denial therefore stops before the suite starts. The runner forwards caller arguments and grants `--allow-read --allow-write --allow-env --allow-run --allow-sys`. Local discern gates use the JUnit report format for structured diagnostics. Hosted gates and bare tasks use Deno's pretty reporter. Both run the same tests. The suite invokes the engine through `deno run src/main.ts` and shells out to Git. Deno runs test modules in parallel and shuffles tests under one explicit [checkout-identity seed](../30-worktrees/identity-and-env.md).

This repository sets `[gate].concurrent_test_runs = 2`. Across the main checkout and every linked worktree, two `done`, `test`, or measuring `standards` test-stage groups may run at once. The cap schedules whole runs only. Complete macOS runs queue smaller native partitions through one process slot per available logical processor, with one worker in each process. Partition count is eight times the logical processor count, independent of Deno's cache and diagnostic output. The checkout's explicit seed orders admission; the same seed still reaches native test shuffling. The runner gives changed test files and resolved importers of changed source priority after the full graph check. The same checkout seed orders those files; the remaining partitions use native discovery with the priority files excluded, preserving the full selection within the same process budget. Configured exclusions remain in both selections. Unsupported caller selections or unavailable import metadata fall back to ordinary seeded admission. Runtime-created imports may remain in the later selection. Each free slot takes more work. Detached subprocess creation otherwise contends with the runtime's allocator across workers. Deno's own discovery and `--shard` divide the remaining file set inside one admitted test-stage group. The shared [priority resolver](../../../scripts/test_priority.ts) uses the repository diff and Deno's resolved code and type dependency graph; its inventory chooses priority candidates and never limits the full native selection. One native `--no-run` preparation checks the complete test graph before any partition runs; runtime children use `--no-check` after that successful check within the same producer. Focused runs and the canary retain three workers in one process. Other platforms retain Deno's native selection. An explicit `DENO_JOBS` always selects one process and takes precedence, including invalid input for Deno to diagnose. Arguments that select files, alter discovery, request watch mode, or provide their own report destination also retain native single-process behavior. This policy belongs to the repository runner; it neither changes the queue cap nor divides capacity by possible fleet load. [`tests/test_runner_test.ts`](../../../tests/test_runner_test.ts) and [`tests/test_partitions_test.ts`](../../../tests/test_partitions_test.ts) preserve enrollment, allocation, and caller overrides.

To compare allocations, run the same focused files with explicit `DENO_JOBS` values and `--shuffle=<seed>` through `deno task test`. Keep instrumentation identical and run the trials serially. Isolated guard timings cannot predict a whole-suite result: a large test process can block other workers during each detached fork. [`scripts/test_partitions.ts`](../../../scripts/test_partitions.ts) keeps every child under the existing ownership boundary and settles all admitted partitions on failure or cancellation. Complete macOS runs keep admitting partitions after test failures and let each native partition collect all its failures. Cancellation still stops admission and settles active children. A JUnit run retains native case XML; a complete selection requires every report. If a child crashes or a run is cancelled, available complete partition reports remain diagnostic evidence under an explicit `discern-selection="incomplete"` marker with reported and expected partition counts. Missing tests have no verdict; partial reports cannot make the producer pass or publish full coverage. Root time is elapsed partition-batch time, including startup and shutdown; case times remain native Deno readings.

Checkpoint gate and acceptance journeys are grouped by declaration, policy, CI, command predicates and evidence so native file partitions can schedule them independently; the former rendering module's cases live on as steps inside the acceptance journeys. Their [gate fixture](../../../tests/engine_checkpoints_gate_fixture.ts) and [acceptance fixture](../../../tests/engine_checkpoints_accept_fixture.ts) share definitions with the [surface probes](../../../tests/engine_checkpoints_surfaces.ts); every top-level journey builds and cleans up its own repository through `withTempDir`, and consolidated former cases run as named steps inside it. Keep native test registration in the case files. Splitting files changes scheduling, so report that benefit separately from reductions in executed work.

MCP fixtures distinguish normal EOF from emergency teardown. Normal shutdown waits for active calls, including environment restoration and durable settlement, within the existing call-readiness allowance. Input closure, server exit and output draining share that deadline. On expiry the fixture forces the owned server down, aborts its output drains and bounds exceptional cleanup separately. Neither a killed child nor a closed input pipe alone proves that the server has finished returning its environment.

### Review execution cost

The [test execution review](test-execution-review.md) explains when to share results, copy fixtures, or chain compatible states. The `test-execution-cost` checkpoint selects growth in expensive test calls and repetition. It leaves assertion-only changes outside the question and requires no timing benchmark. The review preserves each assertion's meaningful preconditions and the real process boundaries under test.

### The canary job

`[jobs.canary]` in [discern.toml](../../../discern.toml) runs a small, cheap subset of the suite at the check stage. `discern prepare` therefore reports a tripped content or structure guard in seconds, and in `discern done` a red canary ends the concurrent check-and-test group early under `[gate].fail_fast`. Every member also runs in the test stage, so a green gate proves the same thing with or without the canary; the job changes how quickly a failure is heard. The canary imports the full runner's command builder, including explicit shuffle, and forwards caller arguments before its derived file list.

Membership derives in [`scripts/canary_registry.ts`](../../../scripts/canary_registry.ts): every guard- or enrolment-named module under `tests/` enrols the moment it exists, the registry's extras add hot files outside that convention, and its exclusions record files refused for cost. [`tests/canary_registry_guard_test.ts`](../../../tests/canary_registry_guard_test.ts) holds every entry to a tracked module with a one-line reason. The canary runs outside `discern queue`: the fleet cap paces whole-suite runs, and a seconds-scale subset must not wait behind one.

Revise membership on evidence: `discern scripts canary-audit` ranks the [Logbook](../70-reference/the-logbook.md)'s recorded per-file test failures against the registry and names hot uncovered files and extras with no record left. The report is advisory — failure history differs per machine, so it never joins the gate.

### Test order and replay

Every suite and canary prints `Test shuffle seed: <number>`. The default is the POSIX checksum of the full branch: stable within an effort, varied across branches, and constant on the trunk. Reuse it to replay a failure or choose another probe:

```sh
deno task test --shuffle=3036198796
deno task test --shuffle=1
```

Bare `--shuffle` is refused because Deno hides its random seed. Tests treat declaration order as meaningless. Shared contracts use one case list that registration and audit both iterate; each test derives evidence from that declaration. The excluded [`order_dependent.ts`](../../../tests/fixtures/order_dependent.ts) fixture proves the runner's seeded shuffle exposes that dependency ([ADR 0350](../_adr/0350-checkout-identity-supplies-test-order-seeds.md)).

Final local validation on 2026-08-27 ran all 4,829 tests green: checkout seed `3036198796` in 7m35s, seed `1` in 7m50s, and seed `2` in 7m06s. Pre-change seeds 1 and 2 took 7m49s and 7m00s. The one-second worst-case shift and overlapping ranges show no measurable regression.

### Deno runner decisions

These verdicts use Deno 2.9.5's local help and official [`deno test` reference](https://docs.deno.com/runtime/reference/cli/test/) and [testing guide](https://docs.deno.com/runtime/test/). Timings are warmed Apple-silicon wall times.

| ------------------------------ | ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Explicit `--shuffle=<seed>`    | Adopt in the canonical runner.                             | Guards order independence reproducibly on every run. Its identity read and permutation have no measurable cost; the full comparison is above.                                                                                                                                                                                                      |
| `--changed`                    | Reject as automatic selection, including the landing Gate. | Ten clean Logbook red commits produced 24 failing modules. Deno selected 2 modules and none that failed: 24/24 misses. Runtime reads of templates, Map content, config, generated trees, and scaffolded projects are graph-invisible. A 0–2-second preflight cannot rescue unsound selection.                                                      |
| `--related`                    | Park as an explicit source-module diagnostic.              | It shares the graph blind spot. Use it only for known direct imports; file and name filters remain the targeted inner loop.                                                                                                                                                                                                                        |
| `--doc`                        | Reject as a standing job.                                  | Repo-wide `--doc --no-run` costs 5.67s and finds 27 type errors in 11 contextual Map excerpts; `src/` costs 0.13s and has no examples. Existing integrity checks and checkpoints own Map fences.                                                                                                                                                   |
| Snapshot testing               | Park for a future large, stable, reviewable value.         | There are no snapshot calls or directories. Add one only when golden-file review beats semantic assertions; continuous integration must never update it.                                                                                                                                                                                           |
| `--repeats`                    | Park as a narrowed hand-run diagnostic.                    | Every repetition must pass and adds a complete execution: about 7–8 minutes locally or 45 minutes hosted.                                                                                                                                                                                                                                          |
| `--retry`                      | Reject.                                                    | Passing when any attempt passes conceals flakes and adds red-run cost.                                                                                                                                                                                                                                                                             |
| Global ops/resource sanitizers | Park; use them on the test that owns the risk.             | The 337-test canary passes at 10.72s versus 10.60s (+1.1%). No recorded leak class yet justifies a full-suite exception contract.                                                                                                                                                                                                                  |
| `--trace-leaks`                | Park as a hand-run sanitizer diagnostic.                   | The canary takes 10.77s (+1.6% wall, +13.6% user CPU). Run it after a leak signal.                                                                                                                                                                                                                                                                 |
| GitHub Actions `--shard`       | Park.                                                      | Two ideal shards could cut 45 minutes toward 22.5, but partial runs cannot form one Gate Proof. Retaining the required full Gate plus a shard spends another suite without shortening the required job. CI advice remains one full Gate. Internal test partitions belong to that Gate's single producer; separate partial Gates cannot pool Proof. |
| `--coverage-threshold`         | Reject as a second authority.                              | The shared coverage recipe already owns the module floor and exceptions. A second threshold repeats minutes of work for a weaker aggregate.                                                                                                                                                                                                        |
| Wider fake-time use            | Reject.                                                    | `Clock` and `Scheduler` own time policy. `FakeTime` stays limited to timer order or cancellation; a global replacement would cross test boundaries.                                                                                                                                                                                                |

Selection flags never enter `discern done`; landing remains full-suite. Add an inner-loop accelerator only after replay proves it preserves failures and improves wall time.

### Project-control integrity

`[jobs.project-control]` runs [`project_control_integrity.ts`](../../../scripts/project_control_integrity.ts) at the gate's check stage. The read-only command derives private planning programmes and numbered briefs from the optional overlay, parses every open [`project/TODO.md`](../../TODO.md) item, compares each documenter scope manifest with its live numbered map subtree, and resolves page-shape names and default budgets from `project/map/_internal/page-templates.md`. A public clone without `_private` remains valid; present private content receives the full link, state, dependency, literal worktree identity, and planned-output checks.

[`project_control_integrity_test.ts`](../../../tests/project_control_integrity_test.ts) plants each failure class in isolated trees. Its valid fixtures include the absent-overlay case and a declared future output before creation; negative fixtures cover missing and stale members in both directions. Run `discern scripts project-control` for the same quiet repository check without the rest of the gate.

The site tests read the built site, which the gate's build stage produces through `deno task site:build`. On a fresh checkout that has never run the gate, run `deno task site:build` before the full suite. The `test.exclude` list in `deno.json` keeps generated output, distribution files, templates, and fixtures out of discovery.

Tests work at these layers:

- **In-process tests** call the production parser, planner, result core, or renderer that owns a decision. Put input variants here and drive them from a table when they share one contract.
- **Installer tests** drive the Deno command-line interface (CLI) as a real subprocess through `runCli` ([tests/helpers.ts](../../../tests/helpers.ts)). They exercise Cliffy parsing, global flags, JSON and Markdown result output, and exit codes through the CLI boundary.
- **Engine tests** (`tests/engine_*`) scaffold the real `templates/` directory, including the `discern.toml` seed, into a temporary directory through the installer's plan and apply path. They then run the Engine as a real subprocess through `runAgent` ([tests/engine_helpers.ts](../../../tests/engine_helpers.ts)). Each test runs `deno run src/main.ts <verb>` inside that directory, with a `discern` shim on `PATH` so Project Scripts resolve. The tests exercise Engine verbs such as `done` and `worktree`, including their JSON and Markdown result contracts, against a faithful install.
- **Decode JSON before assertions.** Pass a command's `--json` stdout to [`decodeCliResult`](../../../tests/decode_cli_result.ts); it validates the decoded value against the command's registered Zod schema. Use its `decodeWith` for fixture and sidecar JSON. [`raw_json_parse_guard_test.ts`](../../../tests/raw_json_parse_guard_test.ts) bans direct parses across the Git-derived test and executable-fixture universe except the decoder.

The product manual has one cross-layer contract. [`manual_curation_test.ts`](../../../tests/manual_curation_test.ts) guards physical admission, required metadata, sections, routes, and promoted links. [`manual_policy_test.ts`](../../../tests/manual_policy_test.ts) guards kind policy, Human Benefit obligations, and the exact manual prose projection. [`manual_doc_checkpoint_test.ts`](../../../tests/manual_doc_checkpoint_test.ts) exercises every purpose-specific checkpoint against additions, modifications, deletions, withheld pages, malformed inputs, and future registry members. [`manual_surface_parity_test.ts`](../../../tests/manual_surface_parity_test.ts) compares stable page ids across CLI, MCP model, site, search, raw and export inputs, sitemap, `/llms.txt`, redirects, and build staging. [`site_docs_test.ts`](../../../tests/site_docs_test.ts), [`docs_test.ts`](../../../tests/docs_test.ts), and [`engine_mcp_test.ts`](../../../tests/engine_mcp_test.ts) retain representative real delivery boundaries. Together they prove one source cutover rather than independent per-surface content lists ([ADR 0314](../_adr/0314-separate-public-manual-and-project-map.md)).

Prose tests keep the two corpus economics separate. The existing `prose` job and standard continue over the configured map. Manual product voice and reading complexity consume only the canonical published manual projection; frontmatter and code are removed before measurement, and reference pages remain in voice and exactness checks while staying outside the reading-grade denominator. The public leaf-density standard uses the same manual projection, so withheld pages cannot influence one measure but not another.

**Keep tests independent.** Every test-side temporary directory comes from [`tests/temp_dir.ts`](../../../tests/temp_dir.ts). Ordinary tests and executable fixtures use the generic `withTempDir` callback; its options cover custom parents, prefixes, and exact-path renames, and teardown removes the owned tree plus its sibling worktree root with a retry for finishing-child races. The suite-scoped form is reserved for the module-level `TMPDIR` that `engineEnv` injects into every spawned engine. It unloads with the test process, while a killed process leaves a registered `discern-test-` entry for the artifact reaper ([ADR 0249](../_adr/0249-self-shims-cache-per-identity-sweep-pages-stay-budget-bounded.md)). [`tests/temp_dir_guard_test.ts`](../../../tests/temp_dir_guard_test.ts) binds this authority into the repo-wide raw-creator guard described below.

**Keep tool scratch callback-scoped.** Standalone repository commands create ephemeral work only through [`scripts/temp_dir.ts`](../../../scripts/temp_dir.ts). Its registry separates command scratch from both test fixtures and retained runtime artifacts: the callback owns the path, settlement removes it by default, a cleanup failure fails an otherwise successful command, and an already-failing command keeps its primary error while reporting teardown trouble. A preserve-on-failure kind must declare that exception and report the retained path. The same [`temp_dir_guard_test.ts`](../../../tests/temp_dir_guard_test.ts) scans the complete Git-derived TypeScript universe, including executable fixtures, and permits raw directory creation only in the three reasoned authority modules.

### Waiting and time boundaries

**Wait for observable conditions.** [`waitUntil`](../../../tests/waiting.ts) evaluates an eventual condition immediately, yields through an injected scheduler between attempts, and reports the condition plus bounded timing evidence when it expires. Use it for filesystem appearance or disappearance and other eventual state that does not depend on a still-pending operation. Supply fixed wall and monotonic clocks plus a deterministic scheduler when the subject is retry arithmetic or wait-bound calculation. A wall-clock jump must not change elapsed duration. Use `FakeTime` only when the subject is actual timer scheduling, callback order, or cancellation ([ADR 0347](../_adr/0347-clock-scheduler-and-jitter-are-explicit-capabilities.md)).

**Assert a budget at its owning layer.** A producer timeout excludes repository preparation and environment return. Even its measured duration can exceed the configured budget when the host dispatches the timer late. Use an injected scheduler to prove the requested delay, timeout attribution, escalation order, and awaited child settlement; retain real process tests for signals and pipe cleanup. A full command proves its diagnostic and final state. Its total duration cannot establish a nested producer's deadline.

[`test_elapsed_guard_test.ts`](../../../tests/test_elapsed_guard_test.ts) enrolls host monotonic reads and paired wall-clock duration subtraction across Git-derived test modules and fixtures. Each retained measurement declares its exact enclosing boundary, sample count, and reason in [`test_elapsed_boundaries.ts`](../../../tests/test_elapsed_boundaries.ts). A new helper or alias requires review; raw host primitives are separately guarded. The census does not prove that a reviewed interval's semantics remain correct. Injected clocks and civil timestamps are outside this host-duration census.

**Keep readiness separate from behavior.** When a test starts an asynchronous operation and waits for its planted file, output, or state marker, call [`waitForPendingCondition`](../../../tests/waiting.ts) with both the pending promise and the positive condition. It uses the suite's one load-safe process allowance, fails immediately when the operation settles before its marker, and prevents Deno's parallel worker scheduling from consuming a behavioral deadline. Once the marker exists, a real timing contract at its owning layer may use an explicit short bound; [`settlePending`](../../../tests/waiting.ts) makes that post-readiness budget visible. Do not shorten readiness to make a test fast: early settlement supplies the fast failure path, while the gate remains the outer hang bound.

[`await_readiness_guard_test.ts`](../../../tests/await_readiness_guard_test.ts) scans the Git-derived test universe for a pending operation followed by a raw condition wait, including operations later joined through `Promise.all`. Its adversarial fixtures use unrelated names and a fresh helper, so a new test module or wrapper enters without extending a known-name list. The guard also keeps behavior clocks after observable job-runner readiness.

A test uses a JavaScript timer only through `realDelay` with a literal id from [`TEST_REAL_DELAY_BOUNDARIES`](../../../tests/waiting.ts); each registry row names the exact path, enclosing test or helper, operation, reason, and semantic classification ([ADR 0340](../_adr/0340-tests-wait-on-conditions-and-enrol-real-delays.md)). Retained intervals assert elapsed behavior, complete a negative-observation window, or supply controlled adversarial timing or ordering. Expiry must never establish that eventual external state, streamed output, or an interaction boundary is ready.

[`test_waiting_guard_test.ts`](../../../tests/test_waiting_guard_test.ts) scans Git-derived test directories and native test entry names at any depth, including executable fixtures and child-program source embedded in strings. It rejects direct timers outside the capability and binds registry entries to literal calls in both directions. `deno task test-real-delay-boundaries` runs the same parity check, reports the recorded classification totals, and emits the census; `[standards.test_real_delay_boundaries]` holds that registry population under a falling ceiling. The census measures population, not whether a row's semantic justification is true.

Shell commands follow the same readiness rule. [`test_shell_wait_guard_test.ts`](../../../tests/test_shell_wait_guard_test.ts) scans that universe through syntax, including literal declarations, static concatenation, templates, and shell fixtures. Every remaining elapsed command is bound to its enclosing scope, argument, occurrence count, and reviewed purpose in [`test_shell_wait_boundaries.ts`](../../../tests/test_shell_wait_boundaries.ts). A new command, copy, argument, or fixture container requires enrollment. Polling paces a condition check; watchdog tests exercise elapsed behavior. Commands that must survive until cancellation hold indefinitely. Arbitrary runtime-generated command text is outside this static census, and semantic justification still requires review ([ADR 0383](../_adr/0383-test-shell-waits-require-observable-transitions.md)).

A transient output frame needs an acknowledgement before the producer replaces it or exits. [`shell_barrier.ts`](../../../tests/shell_barrier.ts) supplies an owned FIFO for shell fixtures; place it outside the fixture repository and release each phase only after the PTY driver observes the required output. The terminal resize fixture observes the initial frame, changes the kernel size, and waits for a new stable job fact before releasing the output producer. That fact proves the renderer processed the changed viewport. Stable lifecycle facts need no artificial delay. A renderer may coalesce partial updates between redraws while preserving the complete raw output artifact.

The `terminal-timing-readiness` stop checkpoint fires when a waiting or elapsed-measurement registry, its enrollment guard, or a generic PTY/TTY synchronization and capture boundary changes. It asks whether every changed transition reserves elapsed time for behavior or controlled stimulus and uses positive observation for readiness and frame completion. A future real delay reaches that judgment through the registry choke point even when its fixture has an unrelated name.

**Inject time according to its meaning.** Fixed `Clock` implementations prove timestamp formatting, expiry, duration, percentile, and freshness calculations without globally changing the runtime. Give wall and monotonic reads independent sequences when a test needs to prove that civil-time movement cannot corrupt elapsed-time behavior. `FakeTime` proves the system scheduler adapter's timeout/interval ordering and cleanup. Direct clock, timer, and jitter primitives outside their system authorities fail the repository-wide ambient-state guard, so a new test helper receives the capability rather than opening another primitive boundary.

When a test needs Git, it uses a repository from `gitInit` with its own config, no signing, and a `main` branch, which prevents global Git settings from affecting it. Each scaffolded project's per-identity shim lives in its own `.git` directory and is removed with the scaffold. Each test owns its fixtures, touches no shared state, and assumes no ordering. Keep all access inside the temporary directory and independent of other tests' side effects. The [Gate gotchas](done-gate-gotchas.md) explain what to check when a test passes alone but fails in the full run.

## How tests are written

- **Test each decision at its production seam.** Put a variant matrix in an in-process test, then keep a representative `runCli` or `runAgent` case for CLI parsing, output, exit codes, and boundary wiring. When a canonical set must cross a boundary, stub unrelated engine work there instead of repeating the complete engine for every member. Each subprocess loads the CLI and may start Git or project commands, so reuse an existing boundary fixture when it already crosses the same path. The helpers disable color with `NO_COLOR`, so boundary assertions match plain text.
- **Scaffold from the real templates.** Engine tests use `scaffoldEngine` (which lays down `REAL_TEMPLATES` through `assembleInitPlan`/`applyPlan`), so the bytes under test are the bytes a real `discern setup begin` ships. Use `writeConfig` to set the `[jobs]`/`[scopes]`/`[standards]` a case needs, and `addWorktree` for the worktree-command layout.
- **Use fixtures for unit-level installer tests.** `FIXTURE_TEMPLATES` plus `testTokens` give a small synthetic tree for testing rendering/plan logic in isolation, separate from the full real templates.
- **Assert convergence where it matters.** `snapshotTree` and `assertConverges` express the invariant that upgrade output equals fresh-init output ([ADR 0014](../_adr/0014-versioned-migration-system.md)). Use them when a change touches the install, upgrade, or migration path.
- **Put coverage in the right place.** Test Engine behavior in `tests/engine_*_test.ts` and installer behavior in the other `tests/*_test.ts` files. Each Engine verb is exercised by a subprocess test through `runAgent`, so add a driving test in `tests/engine_*` for a new verb.
- **Own live subprocesses lexically.** Live Model Context Protocol (MCP) cases bind each server with `await using` in [`engine_mcp_test.ts`](../../../tests/engine_mcp_test.ts). The asynchronous disposer closes standard input, waits for cancellation, and escalates to process signals when shutdown stalls. A response timeout rejects only after that cleanup. A structural test refuses a future `spawnMcp` call without the disposal binding.
- **Start behavioral clocks and transitions at readiness.** Await tests observe a continuation marker written after the core captures its baseline before they mutate Git state ([tests/engine_await_test.ts](../../../tests/engine_await_test.ts)). A fixed sleep is not readiness evidence. [`tests/await_readiness_guard_test.ts`](../../../tests/await_readiness_guard_test.ts) scans every authored test module for that timing assumption and for a `runParallel` clock started before the run. Process-level timeout tests follow the same rule: plant a marker when the behavior begins, wait for the marker or an early process exit, then start the elapsed-time assertion. The shared PTY driver waits for every scripted input marker under its infrastructure allowance, then starts an explicit completion deadline after the final input. An initialized MCP test call has no later request-readiness marker, so successful responses retain the infrastructure allowance; a test of timeout behavior passes its short deadline explicitly. Machine load therefore cannot spend a product behavior's deadline before that behavior is observable.
- **Keep the Map valid.** `tests/map_integrity_test.ts` validates every fenced `discern …` example against the live verb and flag registry, every intra-Map link and heading anchor against the shared renderer, and the published tiers' audience boundary. `tests/cli_reference_codegen_test.ts` holds the generated CLI reference to the registry. Quote exact commands and paths; the Gate checks them ([ADR 0146](../_adr/0146-docs-integrity-gate-and-generated-cli-reference.md)).
- **Use vocabulary from the term registry.** Synonyms retired by an entry are banned from every live surface by `tests/vocab_drift_test.ts`. Every known job, stage, and top-level verb must be named by the glossary or recorded absent with its reason by `tests/glossary_enrolment_test.ts`. The `vocabulary` Standard holds dead terms and bold-faced redefinitions at zero. Link a term's entry (`**[term](../00-orientation/glossary.md#term)**`) instead of restating it ([ADR 0167](../_adr/0167-term-registry-polices-the-vocabulary.md)).
- **Keep the feature account aligned with the feature registry.** A feature-canon node must claim every top-level verb, known job, stage, config table, bundled Skill, and agent provider, or record its absence with a reason. Every claim must name a live member, and the committed canon page must match its generator (`tests/feature_canon_enrolment_test.ts`, `tests/feature_canon_codegen_test.ts`; [ADR 0175](../_adr/0175-the-feature-canon-compiles-from-a-feature-registry.md)).
- **Keep the canon's plain-language register aligned.** Every feature node carries a required `plain` account with type-checked `why` parity. The committed plain page must match its generator. `tests/feature_canon_plain_register_test.ts` holds the register: a plain lexicon paired with the glossary, plus a jargon scan over every plain string outside code spans. A new term fails until its plain rendering is decided. The `plain_reading_grade` Standard holds simplicity as a falling ceiling ([ADR 0228](../_adr/0228-the-feature-canon-carries-a-plain-language-register.md)).
- **Keep the Human Benefit Canon commercially useful and covering.** Every feature node is cited by a human-benefit entry's `drawsOn` or recorded absent with its reason (a record that is also cited fails as stale), and every public claim in the brand ledger is carried by at least one benefit. A stranded citation fails. Each entry separates human value from the reason it follows, while the generated commercial body excludes claim slugs, evidence-class labels, and inline caveats (`tests/feature_canon_human_benefit_test.ts`; [ADR 0268](../_adr/0268-the-benefit-canon-transposes-the-feature-registry.md); [ADR 0270](../_adr/0270-the-benefit-canon-separates-value-from-claim-qualification.md)).
- **Keep the Agent Benefit Canon exhaustive and outcome-first.** Every feature node has one coding-agent role: direct value, supporting infrastructure, or a reasoned human-only absence. Supporting nodes stay leaves under a directly cited parent. ## Coverage

Line coverage of the product `src/` tree is measured by `deno task coverage` ([scripts/coverage.ts](../../../scripts/coverage.ts)). [`source_module_universe.ts`](../../../scripts/source_module_universe.ts) narrows the Git-derived `authored-deno` scope to `src/`, so future modules join automatically. Syntax classification separates executable, erased type-only, and no-line modules. [`coverage_lib.ts`](../../../scripts/coverage_lib.ts) joins LCOV observations to that universe: an unloaded executable module receives zero, while an LCOV-only or mismatched path produces a diagnostic. [`coverage_lib_test.ts`](../../../tests/coverage_lib_test.ts) plants each state; [`source_module_universe_test.ts`](../../../tests/source_module_universe_test.ts) proves future-root enrollment. Runtime modules avoid Deno's test-source file names so the reporter cannot mistake them for tests ([ADR 0342](../_adr/0342-git-elects-module-coverage-membership.md)).

One complete instrumented suite and its combined LCOV artifact produce three metrics. `[standards.coverage]` holds the aggregate measured-line rate. `[standards.module_coverage]` holds 80% line-floor violations at zero while diagnostics retain the failed set. Exact legacy debts live in [`module_coverage_exceptions.ts`](../../../scripts/module_coverage_exceptions.ts) with their baseline, owner, reason, and recovery. New or regressed low modules, unloaded modules, and stale exceptions fail. `[standards.module_coverage_exceptions]` is the registry's falling ceiling. [ADR 0342](../_adr/0342-git-elects-module-coverage-membership.md) records the trade-offs.

The `coverage`, `module_coverage`, and `module_coverage_exceptions` standards consume `jobs.test`, whose exact command is `deno task coverage`. One instrumented suite supplies all three captured readings during local and CI completion. The producer remains bound to its candidate while external identity is uncertain. [`coverage.ts`](../../../scripts/coverage.ts) awaits profile reporting and scratch cleanup before returning. Local gates select JUnit; hosted gates select pretty output. The 180-minute producer and larger enclosing job budgets retain the uncalibrated hosted limitation until a hosted instrumented run supplies calibration.

[`coverage_profiles.ts`](../../../scripts/coverage_profiles.ts) collects every test partition's separate raw directory and keeps each module's observations in one report shard so native range merging remains complete. Report filenames are unique across input directories, even when original filenames collide. Identical recognized profiles share a representative whose range counts equal their sum. Unknown formats, inexact count sums, and identities beyond the memory budget retain their raw observations. [`completion_baseline_recipe_test.ts`](../../../tests/completion_baseline_recipe_test.ts) compares native LCOV coordinates and counts against the same unmodified inputs. Foreign profiles are discarded during classification, and repeated originals only after their weighted representative has been written. Disposal stays within the awaited processing lifetime so final cleanup avoids a second metadata pass over those files. Workers settle before cleanup, including after a read, removal, or report failure; phase timings remain visible on failed runs.

A failed instrumented suite still finishes LCOV reporting when profiles are available, so the same run names test failures and coverage gaps. Those readings are diagnostic only: the producer retains its failure, emits no successful metric records, and publishes no coverage artifact. Startup failures without profiles cannot supply coverage. Scratch cleanup is awaited on both paths.

## Terminal interaction

Semantic terminal behavior belongs at the deterministic production seam that decides it. [`terminal_interaction_test.ts`](../../../tests/terminal_interaction_test.ts) drives the production adapter with scripted input and explicit terminal dimensions for admission policy, defaults, validation, grouping, search identity, navigation byte sequences, Unicode editing, focus, and short or tall viewport fitting. Gate-family presentation tests inject the viewport and typed job state. The desk splits state and legality into [`engine_desk_model_test.ts`](../../../tests/engine_desk_model_test.ts), dispatch and effects into [`engine_desk_runtime_test.ts`](../../../tests/engine_desk_runtime_test.ts), and responsive content into [`engine_desk_view_test.ts`](../../../tests/engine_desk_view_test.ts). Fleet size, Unicode content, layout, mode policy, and visible-cell focus therefore fail without an operating-system process or scheduler.

A real pseudo-terminal remains only for properties created by the host boundary: raw or canonical line discipline, terminal end-of-input and signal delivery, kernel resize delivery, mode and cursor restoration, control rendering and hardware wrapping, descendant cleanup, and BSD or util-linux `script(1)` transport. [`REAL_PTY_CONTRACTS`](../../../tests/real_pty.ts) is that closed set. Every test uses `realPtyTest` to name its contracts and whether it is a retained canary; terminal review tools use the equivalent `withRealPtyBoundary`. The canonical driver rejects an undeclared caller before constructing a transport and adds the boundary name and host platform to its phase, readiness, and raw-transcript failure evidence ([ADR 0355](../_adr/0355-real-pty-tests-declare-os-boundary-contracts.md)).

[`real_pty_guard_test.ts`](../../../tests/real_pty_guard_test.ts) is the permanent class guard. Its Git-derived TypeScript universe includes executable fixtures and terminal review scripts, so a future directory joins without a file-list edit. The guard permits PTY and terminal-mode primitives only in the canonical driver and resize fixtures, validates literal declarations, and requires every contract to retain at least one canary. Its adversarial controls plant a transport in a fresh fixture container and call the canonical driver from a fresh consumer; both fail without changing the guard's cases.

Retained canaries remain ordinary discovered Deno tests. [`deno task test`](../../../deno.json) is the canonical suite used by the gate, so the same declarations run in the complete Ubuntu lane and in the configured macOS and WSL 2 lanes in [`gate.yml`](../../../.github/workflows/gate.yml). There is no second full-suite workflow or manually duplicated canary inventory.

The shared PTY driver gates every input phase on an authored marker, ordered marker sequence, or positive condition over output newly observed in that phase. Named captures declare a separate positive completion condition. Live resize journeys observe the first complete frame, permit the child to resize out of band, observe the kernel acknowledgment, trigger repaint input, and wait for a complete resized frame before continuing. Elapsed quiet time is never frame evidence. Completion deadlines begin after the final scripted input. Public-command journeys and viewport tests inherit the shared process allowance; only lower-level transport tests set deadlines to exercise timeout behavior. Retained delays exercise elapsed behavior, negative-observation windows, partial writes, or controlled adversarial ordering; they do not infer readiness. An intentional lone Escape declares that boundary because delayed continuation could otherwise turn a key-sequence prefix into cancellation.

[`pty_process_test.ts`](../../../tests/pty_process_test.ts) proves the canonical transport's line discipline, input-pipe lifetime, shell isolation, geometry, readiness conditions, completion deadline, and descendant teardown. [`interactive_tty_test.ts`](../../../tests/interactive_tty_test.ts) retains representative Unicode/raw-mode, Ctrl+C/end-of-input, live-resize, and unexpected-fault restoration journeys. [`docs_test.ts`](../../../tests/docs_test.ts) retains one split-reader restoration journey and one failed-pager lifecycle journey; its navigation, search, link, projection, and target matrices run below the PTY boundary.
