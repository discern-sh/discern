# Code conventions

_The rules the tooling enforces, and the conventions to follow when writing code here._

This page expands the **Conventions** section of the project instructions (`project/instructions.md`). The instructions holds the short, agent-facing form. This page gives contributors the full reasoning. Keep both documents aligned with `[jobs]` in `discern.toml`; the written and enforced rules must agree.

## What the Gate enforces

The jobs in [`discern.toml`](../../../discern.toml) are the mechanical rules in the project's final quality check (the Gate). `format`, `build`, `lint`, `typecheck`, `test`, and `smoke` are known names whose stage the Engine derives; `prose` is custom and declares its stage. Run `discern prepare` for fix, declared regeneration, refresh convergence, and check. Run `discern done` for every configured Gate stage.

Every configured Gate command executes from the resolved project root. This remains true when the command-line interface (CLI) runs from a nested directory and when a long-lived Model Context Protocol (MCP) server targets a worktree outside its own process directory. Formatter, check, test, and scope selection therefore describe the same checkout.

The Engine has no `selfcheck` or shell-recipe matrix because it has no second copy to drift ([ADR 0019](../_adr/0019-single-binary-ts-engine.md)). The standalone remote [`install.sh`](../../../install.sh) remains Portable Operating System Interface (POSIX) shell. Continuous integration (CI) runs ShellCheck on it before the repository Gate. The Gate's `build` job is code generation. The release-only `deno task build` stays outside the Gate. [Testing](testing.md) covers the `test` and `smoke` jobs.

## Remove lint suppressions

Deno recognizes `deno-lint-ignore` for one line and `deno-lint-ignore-file` for a file. Both forms are migration debt in this repository. Fix the named rule instead of adding either directive. If a rule is wrong for the repository, change the shared lint configuration and explain that policy change in review.

Run `deno task lint-suppressions` to list the live census. The `lint_suppressions` Standard holds that raw count at a falling ceiling, so a branch may remove directives and cannot add them. After removing one or more, run `discern standards --pin lint_suppressions` to capture the lower limit.

When the count reaches 0, turn the detector into an always-on zero-count test, remove the transitional Standard, and delete the backlog item.

## Conventions to follow

The conventions the tooling cannot fully enforce, but the project still holds:

- **Follow [File ownership](../00-orientation/glossary.md#file-ownership).** Project-owned files are the committed authored files (`project/map/**`, `project/instructions.md`, authored Skills under `project/skills/`, Project Scripts under `project/scripts/`, and `project/TODO.md`); edit them in place. Shared files include `discern.toml`, provider settings, and discern's `.gitignore` block. Generated files include the ignored `.claude/skills/**` and `.agents/skills/**`, plus the agent files `AGENTS.md`/`CLAUDE.md`/`GEMINI.md`, which are committed and regenerated from their sources ([ADR 0019](../_adr/0019-single-binary-ts-engine.md), [ADR 0128](../_adr/0128-enumerated-ownership-tracked-guidance.md)). The Engine, built-in Skills, and built-in instructions exist only in the binary of an installed project. Change them by editing the source here and rerunning the producing command. See [install-surface.md](install-surface.md) for the full ownership inventory.
- **Regenerate the agent files.** `AGENTS.md`, `CLAUDE.md`, and `GEMINI.md` are compiled from discern's built-in instructions plus your `[instructions].sources` by `discern refresh` and committed ([ADR 0034](../_adr/0034-agents-md-untracked-currency-check.md), [ADR 0128](../_adr/0128-enumerated-ownership-tracked-guidance.md)). Edit the instruction source, run `discern refresh`, and commit the generated files. They carry no banner. `discern done` reports a stale or hand-edited file and gives the recovery action.
- **Run from source; avoid `dist/`.** `discern <cmd>` runs the Engine of the current checkout (`deno task dev <cmd>` is the zero-setup equivalent); the `dist/` binaries bundle a frozen `templates/` snapshot. Omit `--` before a subcommand.
- **Keep TypeScript modules focused.** Every module opens with a JSDoc block stating its role (see any file under `src/`). [`main.ts`](../../../src/main.ts) is routing only; command logic lives in `src/commands/`, the Engine in `src/engine/`, shared installer and Engine helpers in `src/shared/`, and installer-only helpers in `src/lib/`. Keep modules small and single-purpose.
- **Document every function declaration.** Put a JSDoc block immediately before every authored Deno `function` declaration, including private, nested, and test helpers. Tell the reader something the identifier does not: the behavior, contract, side effect, failure boundary, fixture role, or reason for the helper. “Resolve the widget” above `resolveWidget` fails the rule. [`scripts/function_docblock_lint.ts`](../../../scripts/function_docblock_lint.ts) catches missing and formulaic summaries during normal lint; [`tests/function_docblock_lint_test.ts`](../../../tests/function_docblock_lint_test.ts) runs the same abstract syntax tree (AST) rule over the Git-derived source universe, including files excluded from normal lint ([ADR 0251](../_adr/0251-function-declarations-require-jsdoc.md)). Methods, arrow functions, function expressions, and type signatures are separate syntax families and stay outside this rule.
- **Use strict TypeScript across the repository.** The strict `deno.json` compiler options and lint rules apply across the repository, including the Engine. Keep types sound and remove lint suppressions when you touch their code.
- **Keep development-task vocabulary out of shipped surfaces.** `discern` is both a product and a self-hosting repository. The user's `discern …` commands and the repository's `deno task <task>` aliases coexist. Shipped `templates/` and user-facing binary output use the user's vocabulary. A guard test ([tests/dev_vocab_guard_test.ts](../../../tests/dev_vocab_guard_test.ts)) fails the Gate if repository aliases leak.
- **Describe the current system.** Code comments explain present behavior. The comment-currency guard rejects retrospective markers. When a marker describes current behavior and must remain, add `discern-allow-retrospective: <reason>`. Unused, duplicate, and reasonless annotations fail the guard ([ADR 0053](../_adr/0053-comment-currency-guard.md)). Documentation uses present tense, the canonical nouns from the [glossary](../00-orientation/glossary.md), and American Standard Code for Information Interchange (ASCII) diagrams. Put outstanding work in [`project/TODO.md`](../../TODO.md).
- **Record decisions.** A notable change gets an ADR in [`project/map/_adr/`](../_adr/); overriding a [design principle](../00-orientation/design-principles.md) _requires_ one.

For test-specific conventions, see [testing.md](testing.md).
