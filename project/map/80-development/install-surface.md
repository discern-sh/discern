# Install surface

_The engineering inventory of every project-tree path discern writes or maintains, derived from the same registries as the write boundary._

`discern setup` writes configuration, authored Markdown, provider integration entries, and generated agent artifacts into a project. Every registered path declares a [File ownership](../00-orientation/glossary.md#file-ownership) bucket. Provider-created machine-local state is declared separately as provider-local because discern keeps it ignored and never generates it ([ADR 0170](../_adr/0170-file-ownership-is-registry-data.md)).

File ownership governs edits and overwrites. Copyright and license follow authorship. [Apache-2.0](../70-reference/project-payload-license.md) covers discern-authored portions of canonical project artifacts. Neighboring project, user, provider, and third-party material keeps its existing terms.

## Ownership contracts

| Bucket            | Edit contract                                        | Overwrite contract                                              |
| ----------------- | ---------------------------------------------------- | --------------------------------------------------------------- |
| **Project-owned** | Edit in place.                                       | Setup may seed it. discern leaves it to the project afterward.  |
| **Shared**        | Edit outside discern's marked region or named entry. | discern may replace its region or entry and preserves the rest. |
| **Generated**     | Edit the reviewable instructions or skill source.    | `discern refresh` and `upgrade` rebuild the artifact.           |

Provider-local paths stand outside File ownership. The provider creates and maintains them. discern maintains only the matching ignore rule.

## The write-surface contract

The write boundary consumes the registered inventory. It admits Project-owned, Shared, and Generated entries and excludes provider-local entries. A static funnel confines each raw filesystem mutation under `src/**` to a sanctioned write-site module. A runtime pass runs `setup begin`, `refresh`, and `upgrade`, then rejects any project-tree write outside the registered paths ([`tests/paths_write_surface_test.ts`](../../../tests/paths_write_surface_test.ts), [ADR 0102](../_adr/0102-paths-registry-and-rendered-artifacts.md)).

Runtime records under Git's administrative directory, a user-supplied output path such as `docs --output`, and OS temp artifacts sit outside the project tree. Their writers remain in the static funnel. **[Placement is consent](../00-orientation/glossary.md#placement-is-consent)** for configured project paths: accepting a default or pointing a config key grants the write license; other project paths are untouchable ([ADR 0099](../_adr/0099-consolidate-authored-surface-under-discern-namespace.md)).

## The quality Gate

The project's final quality check (the Gate) is part of the binary's TypeScript Engine ([`src/engine/`](../../../src/engine/)). Its public verbs are first-class `discern` subcommands:

| Command             | What it does                                                                                                                                                                                            | Source                                                                  |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `discern done`      | Runs the full Gate: the trunk-merged precondition in a worktree, built-in currency and write-access preconditions, `fix` plus `build`, `check` plus `test` in parallel, and each applicable scope Gate. | [`src/engine/gate/finish.ts`](../../../src/engine/gate/finish.ts)       |
| `discern prepare`   | Runs the fast inner loop of fixers followed by read-only checks, with no build or test.                                                                                                                 | [`src/engine/gate/prepare.ts`](../../../src/engine/gate/prepare.ts)     |
| `discern test`      | The `test` job on its own.                                                                                                                                                                              | [`src/engine/gate/test.ts`](../../../src/engine/gate/test.ts)           |
| `discern tidy`      | Canonically formats the configured Map, instructions, ledger, and root config. A bare run formats Markdown and TOML; `md` or `toml` selects 1 format.                                                   | [`src/engine/tidy/tidy.ts`](../../../src/engine/tidy/tidy.ts)           |
| `discern standards` | Measures configured metric floors and ceilings when invoked; its built-in write preflight covers the measurement proof, plus config and Git commit state when pinning.                                  | [`src/engine/gate/standards.ts`](../../../src/engine/gate/standards.ts) |
| `discern impact`    | Classifies which scopes the branch touches and fails open: an unknown path runs additional Gates.                                                                                                       | [`src/engine/scopes/scopes.ts`](../../../src/engine/scopes/scopes.ts)   |

Every subsystem is core. The config has no `[features]` table or existence toggle ([ADR 0101](../_adr/0101-retire-the-features-toggles.md)). Worktrees exist only when started, and Standards exist only when defined. `[skills].exclude` remains because materialized Skills occupy agent context even when unused. `[jobs]` is the Gate's command table.

Stage scheduling ([`src/engine/gate/stages.ts`](../../../src/engine/gate/stages.ts)), failure-pointer wording ([`src/engine/gate/gotchas.ts`](../../../src/engine/gate/gotchas.ts)), and the parallel and serial job runner ([`src/engine/jobs/runner.ts`](../../../src/engine/jobs/runner.ts), with process-group tree termination in [`src/engine/jobs/command.ts`](../../../src/engine/jobs/command.ts)) support these verbs. `doctor` ([`src/commands/doctor.ts`](../../../src/commands/doctor.ts)) reports the state of config, Git, job commands, paths, and install readiness.

### Production dependency projection

The repository's root dependency graph serves the product, tests, the site, and repo-internal development tools. [`scripts/build.ts`](../../../scripts/build.ts) does not project that workspace boundary into a release: it resolves npm without the physical `node_modules` directory and embeds only packages reachable from `src/main.ts`. An internal tool can add an npm dependency without changing the production artifact, while a product import automatically enters the same graph used for third-party notices ([ADR 0136](../_adr/0136-third-party-notices-derive-from-the-compile-graph.md), [ADR 0289](../_adr/0289-production-binaries-embed-only-product-reachable-npm-packages.md)). [`tests/build_distribution_inputs_test.ts`](../../../tests/build_distribution_inputs_test.ts) holds the compile flags at that boundary; the binary-size Standard supplies the release-level backstop.

### Embedded formatter

[`src/lib/tidy_format.ts`](../../../src/lib/tidy_format.ts) owns fixed Markdown and Tom's Obvious Minimal Language (TOML) settings and loads vendored dprint plugins from [`src/lib/tidy_plugins/`](../../../src/lib/tidy_plugins/). [`src/lib/toml_indent.ts`](../../../src/lib/toml_indent.ts) composes after the TOML plugin ([ADR 0221](../_adr/0221-depth-indent-discern-toml.md)). [`scripts/build.ts`](../../../scripts/build.ts) embeds the Git-authored plugin and template projection. Exact exclusions reject other physical entries, including host metadata. Repository-wide source guards use the same metadata rule. No plugin download occurs.

Every production writer of `discern.toml` calls the same TOML formatter before writing. The generated-Map side converges at [`scripts/codegen.ts`](../../../scripts/codegen.ts): its single write helper formats every Markdown target before comparing or writing it. [`tests/engine_tidy_test.ts`](../../../tests/engine_tidy_test.ts) holds the real Map and config to idempotence, parse-before-write behavior, scope, fenced-code preservation, and the frontmatter contract. It refuses a block that does not parse and preserves a valid one ([ADR 0184](../_adr/0184-markdown-writers-preserve-or-refuse-frontmatter.md)). [`tests/canonical_sets_enrolment_test.ts`](../../../tests/canonical_sets_enrolment_test.ts) holds every generated Map page to the same fixed point.

## The isolated-worktree workflow

The worktree workflow has no feature toggle or attached configuration ([ADR 0101](../_adr/0101-retire-the-features-toggles.md)). Generic Git mechanics live in the Engine ([`src/engine/worktree/`](../../../src/engine/worktree/)), driven by the hooks in [Bookkeeping and integration](#bookkeeping-and-integration). A project can declare stack-specific resources for each worktree under `[worktree.resources.<name>]` in `discern.toml`. A fresh install declares none.

| Command                        | What it does                                                                                                                     |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| `discern start`                | Creates and sets up an isolated worktree for a change.                                                                           |
| `discern worktree hook create` | Creates and sets up a worktree from the `WorktreeCreate` hook's JSON payload on standard input.                                  |
| `discern worktree setup`       | Sets up a newly created worktree, as `discern worktree hook create` does inside it.                                              |
| `discern worktree ensure`      | Runs repeatable session-start setup for the `SessionStart` hook.                                                                 |
| `discern accept`               | Requires tracked refresh convergence, lands the branch, materializes only checkout-local artifacts, and tears the worktree down. |
| `discern worktree hook remove` | Tries to tear a worktree down from the `WorktreeRemove` hook's JSON payload on standard input.                                   |
| `discern worktree teardown`    | Destroys a worktree's resources, as `discern worktree hook remove` does.                                                         |
| `discern worktree prune`       | Sweeps stale worktrees, fully merged branches, orphan directories, and orphan resources.                                         |
| `discern identity`             | Resolves a worktree's stable identity, including its ID, site, branch, port, database, and resources.                            |

The lifecycle logic lives in [`src/engine/worktree/lifecycle.ts`](../../../src/engine/worktree/lifecycle.ts); the stable worktree identity (POSIX-`cksum`-faithful) in [`src/engine/worktree/identity.ts`](../../../src/engine/worktree/identity.ts). Run `discern --help` for the full verb list.

| Path                                 | Bucket        | What it is                                                                                                                                                                                                                                                                    |
| ------------------------------------ | ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `discern/instructions.md`            | project-owned | The hand-authored instruction source or sources in the default `[instructions].sources`. They add to the built-in instructions, accept globs, and are seeded by `discern setup`.                                                                                              |
| `AGENTS.md`                          | generated     | The canonical agent file. It holds the full compiled body that the mirrors import; Codex, Cursor, and the Copilot command-line interface (CLI) read it natively. It is committed by default (ADR 0128), and a stale copy fails the `discern done` instruction currency check. |
| `CLAUDE.md`, `GEMINI.md`             | generated     | The committed per-agent mirrors. Each contains a one-line `@AGENTS.md` import that its provider expands in place. They have no banner; the currency check detects drift.                                                                                                      |
| `.claude/skills/`, `.agents/skills/` | generated     | Materialized Skills that configured agents discover. Built-in Skills are rendered and authored Skills are symlinked. `discern refresh` ([`src/engine/instructions.ts`](../../../src/engine/instructions.ts)) regenerates the agent files, Skills, and integration artifacts. It compiles the canonical body from discern's built-in instructions followed by the project's `[instructions].sources`. It then writes each provider's full body or canonical pointer and materializes the Skills again. `[project].agents` selects the files through the provider registry ([`src/lib/providers.ts`](../../../src/lib/providers.ts)). The Model Context Protocol (MCP), hooks, and Skills wiring for each agent are mapped in [`../60-agent-integrations/`](../60-agent-integrations/).

The tracked-refresh planner runs provider transformations in memory. It derives the expected Agent files, `.gitattributes`, and ADR index for `status`, `done`, and `accept`; live refresh supplies the paths `update` handles during a merge ([ADR 0264](../_adr/0264-tracked-refresh-convergence-precedes-landing.md)).

## Bundled skills

Bundled agent Skills ship in the binary from [`templates/skills/`](../../../templates/skills/) through the same authored projection. A guard checks the table below against that set. A project can add Skills under `[skills].dir` (default `discern/skills`) and override a built-in by name.

`discern refresh`, `discern setup`, and `discern upgrade` materialize the effective set into each configured agent's generated, Git-ignored Skills directory. The strict template Engine renders built-ins, replacing path tokens such as `{{map_dir}}` with configured paths ([ADR 0102](../_adr/0102-paths-registry-and-rendered-artifacts.md)). Authored Skills are symlinked so edits are live (see [`src/lib/skills.ts`](../../../src/lib/skills.ts)). `discern skills list` shows the effective set and its overrides. `discern skills eject <name>` copies a built-in into the project's Skills directory for customization. `[skills].exclude` drops named Skills from materialization. ## The Map and the ledger

`discern setup begin` creates the Map skeleton at `[map].dir` (default `discern/map/`) and the deferred-work ledger at `[project].todo` (default `discern/TODO.md`). The Map skeleton includes the ADR pack and the `_internal/` documenter brief with its scope-manifest template. The pack ships the format guide, the copy-paste template, and the seeded adoption record `0001-adopt-discern.md`, which the configuring agent completes with the project's real context ([ADR 0283](../_adr/0283-skeletons-seed-the-adoption-record.md)). The setup brief's authoring pass fills both artifacts ([ADR 0100](../_adr/0100-project-map-is-the-agents-map.md), [ADR 0195](../_adr/0195-fresh-maps-and-neutral-scopes-stay-inside-owned-paths.md)). The skeleton sources ship with their producer: [`templates/setup/skeleton/`](../../../templates/setup/skeleton/) for setup and a `skeleton/` directory inside each carrying Skill. The write-adr skill's `_adr/` pack is generated: `deno task codegen` copies it from the setup skeleton, and the byte-identity test backstops the pair ([ADR 0283](../_adr/0283-skeletons-seed-the-adoption-record.md)). The producer copies them to the configured destinations and renders their path tokens ([ADR 0080](../_adr/0080-configured-agent-map-root.md), [ADR 0102](../_adr/0102-paths-registry-and-rendered-artifacts.md)).

> In this repo, the same hooks call `discern worktree ensure`, `discern worktree hook create`, and `discern worktree hook remove`. The local-dev wrapper resolves the nearest checkout's source engine, while the distributed [`templates/.claude/settings.json.tmpl`](../../../templates/.claude/settings.json.tmpl) resolves the installed binary on `PATH`.

The linked worktree checkouts appear only at run time; `discern setup` does not create them. By default they live in a sibling directory (`<repo>.worktrees/`) outside the repository, so nothing in the tree needs to ignore them. When a project points `[worktree].root` inside the repository, such as `.claude/worktrees`, the ignore block keeps them out of Git ([ADR 0052](../_adr/0052-worktree-sibling-placement.md)).
