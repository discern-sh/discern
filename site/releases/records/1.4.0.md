"**Ridgeline**" is discern's v1.4.0 release, focused on improving performance on smaller CI runners and in WSL 2.

## More control over CI runs

- On a runner with little memory, you can limit how many gate commands run at once. Each command gets its full time limit when it starts.
- Set `DISCERN_ENGINE_TIMING=1` to see when each step and command started and how long it took. The timings appear in the logbook.
- When you approve a change to a standard, the CI run after landing can report which limits changed and check the project against the new limits.

The CI guide shows how to set a limit on concurrent commands and report changes to standards. [Run the gate in CI](https://discern.sh/docs/guides/run-the-gate-in-ci)

## Other fixes and changes

- A proposed limit for a standard now includes the margin you configured, so you can see the limit you're being asked to approve.
- The redesigned homepage groups features by what you want to do. Open a card to see how discern helps. [Explore discern](https://discern.sh/)
- On WSL 2, `discern doctor` warns when your checkout is on a Windows drive and suggests moving it to the Linux filesystem.
- discern also skips the contents of ignored directories when checking for changes and makes fewer Git calls during a run, significantly improving performance on WSL 2 and virtualized filesystems.
