Welcome to "**Clearwater**": discern's v1.1.0 release.

## Plain language, wherever you read discern

- Every page of the manual now answers its question in short, direct sentences, with its facts checked against the product.
- `discern --help` gives one short line per command. Each command's own `--help`, and the CLI reference, keep the full detail.
- The comments in a new project's `discern.toml`, the config and environment-variable references, and the glossary use the same voice. Glossary hover cards now appear on product terms, not on everyday words.

## Emergency landings show everything you approve

- The plan lists the commits the repair would land, and names any other task whose unlanded work comes with it. Your approval covers that list, and the emergency record keeps it.
- A looser standard limit lands in an emergency only with your approval of that limit, given with its own token as in an ordinary landing. The plan shows the old and new limit and the reason. A standard can't be redefined or deleted this way.
- A checkpoint the agent answers unmet no longer blocks the emergency route. The plan shows the question and the agent's reasons, and landing needs your variance, as in an ordinary landing.
- An emergency landing still never counts as Proof, whatever you approve with it.

## Fixes

- A landing whose Proof note couldn't be written keeps its worktree until the note is recorded. Run `discern accept` there again to write it; the change doesn't land twice.
- `discern status`, the desk, and `discern enter` no longer crash on an env file they can't read. The affected worktree is marked unreadable instead, and commands that need its identity name the file to fix.
- `discern upgrade` reports the schema version it started from, instead of "recorded none".
- Setup's restart guidance no longer runs a trust sentence into the middle of another.
- When a worktree's setup can't be verified, status and the desk suggest a command that exists.
- `discern skills list --markdown` keeps excluded and overriding skills.
- The `standards --pin` help and the agent tool description say that a pin commit needs a fresh `discern done` before it can land.

## Changed behavior

- `discern uninstall --json` and `--markdown` refuse with `confirmation_required` until you pass `--yes`. A script that used structured output to apply the removal must add `--yes`.
- Recovering an interrupted landing after the trunk has moved on now finishes the landing's remaining steps and cleans up, instead of stopping and asking you to run `discern worktree prune`.
- `discern worktree prune` keeps a worktree whose landing is still settling, such as one that still owes its Proof note.
