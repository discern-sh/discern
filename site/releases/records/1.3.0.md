"**Shoreline**" is discern's v1.3.0 release, focused on sharing a project with other agent tools, such as a framework's agent kit or a skill installer.

## Support for your other agent tools

A new guide, [Use discern alongside other agent tools](https://discern.sh/docs/guides/use-discern-alongside-other-agent-tools), shows how to keep another tool's rules, skills, and settings working beside discern's.

- Skills folders such as `.claude/skills/` are shared. discern owns only the entries it placed, and `discern refresh` and `discern uninstall` keep every other tool's skills.
- If another tool's skill holds a name discern needs, `discern done` stops at its `skills` stage, names each contested entry, and says how to free the name.
- When `discern refresh` would drop lines from an agent file, such as `AGENTS.md`, that no instruction source produces, it lists them and names your choices for keeping them. `discern start`, `discern update`, and `discern accept` report the same lines.
- During setup, your coding agent decides whether you wrote each existing agent file or another tool maintains it. Setup leaves a file named with `--tool-maintained` out of your instruction source, so it doesn't save a copy that goes stale as the tool rewrites it.
- `[instructions].sources` compile in the order you list them, so you choose whether a tool's rules come before or after yours. If you list several sources, the next `discern refresh` may reorder your agent files to match.
- discern's block in `.gitignore` re-includes the integration files your own rules would hide, and your rules keep ignoring everything else in those folders. `discern doctor` warns when an ignore rule still hides one of those files or another tool's skills.
- discern writes its entry into a shared file, such as `.mcp.json`, in that file's own indentation and line endings. Its comment in a shared file names only the part discern maintains.

## Other fixes and changes

- `discern tidy` leaves a file that a `[generated]` group owns to its generator, so the gate no longer reformats generated output and then fails on the difference.
- `discern setup done` names each page or setting that fails and the rule it misses.
- A skill linked into `[skills].dir` from elsewhere in the project now reaches every coding tool. discern reports a broken link, or one that leaves the project, with its fix.
- `discern update` commits regenerated files that your project tracks inside an ignored folder.
- The troubleshooting pages cover another tool writing into an agent file, and an app that starts in a different mode inside a worktree.
