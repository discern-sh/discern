A verdict for agent-written work

Don't take your agent's word for it.

discern runs the checks your repo declares (format, lint, typecheck, test) against the final tree, in an isolated worktree per task, and reports what your commands returned. There's no LLM inside it, no API key, and no network calls. A test can't be talked into passing.

The idea

The repo holds the rules.

Agents come and go. Sessions end, context windows fill, and the next agent starts with no memory of what the last one promised. The repo is the thing that persists, so that's where discern keeps your standards: the checks in discern.toml, the instructions in discern/guidance.md, the standards — numbers that can never get worse — in [standards]. Every agent that shows up inherits them. The ones that show up next year will too.

discern.toml

Checks, declared once

Your format, lint, typecheck, and test commands live in one file. Every agent runs the same ones, and a failure names the command that failed.

discern/guidance.md

Instructions, written once

Edit one source and discern compiles it into CLAUDE.md, AGENTS.md, and GEMINI.md. Every configured agent reads the same rules, with no drift between copies.

[standards]

Limits that hold

A coverage floor can rise and never fall. A size ceiling can fall and never rise. A branch can't loosen a limit to get itself green.

The loop

A task, from start to landed.

  1. 01

    discern start

    A fresh branch in an isolated worktree, beside your repo. Your checkout stays untouched.

  2. 02

    The agent builds

    Ordinary editing and committing, in its own copy. Two agents can work at once without colliding.

  3. 03

    discern done

    Every declared check runs on the final tree. A failure names the tool, shows its output, and hands back a command that reproduces it.

  4. 04

    discern accept

    By default the finished branch is checked out for your review, and the worktree is removed. Nothing lands without you.

The receipt

Done has a receipt now.

A green run over a clean, committed tree issues a receipt bound to that exact commit. discern accept honors the receipt and nothing else — not the summary, not the confidence, and not a tree that changed after the run. Your agent relays it, you read it, and the decision to land stays yours.

Commit again and the receipt is void: whatever lands is always the tree the checks actually saw.

Standards

Limits that only tighten.

A standard is one of your numbers that can never get worse. Discern holds it against main. A floor can rise and never fall. A ceiling can fall and never rise. A branch that loosens either fails, so the only direction a limit moves is the one you wanted.

When a change improves the number, discern standards --pin captures the gain as the new limit. Coverage. Bundle size. The count of @ts-ignore comments you've been meaning to deal with.

discern.toml

[standards.coverage]

direction = "up"     # the limit is a floor

limit     = 82.5

run       = "npm run coverage"

[standards.ts_ignores]

direction = "down"   # the limit is a ceiling

limit     = 7

run       = "echo DISCERN_METRIC ts_ignores $(grep -r '@ts-ignore' src | wc -l)"

Trust

Don't take our word for it, either.

Every claim on this page is checkable from your terminal. Ask your agent to verify them.

No LLM inside

discern runs the commands in your discern.toml, plus its own git and file operations. There's no model to persuade and no API key to configure.

verifydiscern doctor

Zero network calls

No telemetry, no update pings, no uploads. New versions arrive when you re-run your installer, and at no other time.

verifyunplug the network

One file, one folder

The committed footprint is discern.toml plus the discern/ folder you own. A test in the repo fails the moment any verb writes outside the enumerated surface.

verifypaths_write_surface_test.ts

A glance never executes

status, doctor, and the docs browser only observe. Your commands run when you run a check verb.

verifydiscern status

Limits only tighten

Standards are compared against main. Tightening a limit is always allowed. Loosening one is refused.

verifydiscern standards --dry-run

Leaving is cheap

discern uninstall removes the wiring and keeps your content: plain Markdown at paths you chose, readable with or without the tool.

verifydiscern uninstall --dry-run

Why this exists

I spent fifteen years shipping software: startup CTO, team lead, the person promising the board we'd pay the tech debt down next quarter. I know what code written against a deadline looks like, because I wrote plenty of it and managed people who wrote more. Agents moved the deadlines and kept the debt. discern is the discipline I always wanted my teams held to, in a binary an agent can operate: checks that run, limits that hold, and no merging on a confident summary. It was built with the agents it now governs, and it gates its own repository.
