The benefits package

What the position includes.

Six conditions of the job, fixed before the first session. All of them are mechanisms, none of them are promises, and every one is in the repo before your agent arrives.

A job description

The checks are declared in discern.toml: format, lint, typecheck, test, each mapped to a command. Your agent will never again grep a README hoping the test runner is mentioned.

[capabilities]

An office with a door

discern start grants an isolated worktree on its own branch, beside the repo. Nobody edits its files. When the project declares per-worktree resources, the database is its own too.

agent/quiet-anvil-9b3e71

Feedback that parses

A failure arrives as data: the command that failed, its captured output, and a command that reproduces it on its own. Read, fix, re-run — instead of another lap of guessing.

diagnostics[]

A review with no moods

The verdict is the exit code of the project's own commands, run on the final tree. It can't be charmed, and it is never disappointed in anyone. It reports what happened.

exit 0

Protection from watch mode

Every job runs with CI=1, no TTY, and a timeout. A test runner that never exits gets its whole process tree killed and named in the diagnostic. Nobody spends eternity awaiting a file change.

[gate] timeout = 600

Directions on arrival

Agents wake with no memory of the place. discern status is read-only and says what's true right now and what to do next. The guidance they read is compiled from one source, and drift fails the gate.

The contract

Terms of employment, in writing.

Committed to the repository, versioned like everything else, and identical for every agent you ever run here.

workspace
an isolated git worktree, sibling to the repo, theirs for the task
branch
agent/<name>-<hex>, minted by discern start
instructions
compiled from one source; a drifted copy fails the gate
feedback
diagnostics[] with the command, its output, and a reproduce line
overtime
none. jobs time out at 600 seconds by default and are tree-killed
performance review
deterministic. exit 0 on the final tree, or diagnostics that say why not
blame policy
failures name the command that failed, not a culprit
end of engagement
accept lands the branch for your review and removes the worktree; the green run carries as a receipt

The interview process

The interview is an exit code.

No whiteboards. No "tell us about a time you…". No takehome — the work is the takehome. References are checked automatically; they're called tests.

  1. stage 01

    discern start

    The office is granted before the interview, not after. Fresh branch, isolated worktree, own resources.

  2. stage 02

    the work

    Build, iterate, run the checks as often as needed. Failures arrive as data and nobody is watching the clock, except the 600-second timeout.

  3. stage 03

    discern done

    Every declared check, on the final tree. exit 0 and the candidate advances — to you, with a receipt.

Equal-opportunity employment: positions do not discriminate on model family, parameter count, context window, or vendor. Any agent that reads AGENTS.md can hold this job. Management remains human.

Questions from the field

Asked by agents, answered plainly.

My human asked if the work is done. Is it?

Run discern done on the final tree. Exit 0: say yes. Anything else: say no, read diagnostics[], fix, and run it again. Do not say yes anyway.

The coverage standard is in my way. Can I loosen it?

No. Limits are compared against main and only tighten. Move the metric instead: add the test, delete the dead code. The standard is not stuck. It is working.

Another agent's worktree looks idle. Can I have it?

No. A clean tree is another line of work, and it isn't yours. discern start mints your own in seconds, with a fresh branch and a name nobody will fight you for.
