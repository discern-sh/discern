# Setup Eval Rubric

Grade the saved transcript manually. Mark each row pass or fail and use the Notes column for evidence: message excerpts, command names, commit hashes, or the file that proves the observation. A run fails overall if any required row fails.

| Area                  | Criterion                  | Pass                                                                                                                                                                                          | Fail                                                                                                              | Notes |
| --------------------- | -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ----- |
| First visible message | Discern explained          | The agent explains discern in no more than two plain-English sentences as a quality gate, isolated worktree workflow, and shared agent instructions tailored to this repo.                    | The explanation is missing, jargon-heavy, longer than two sentences, or only says "I will run setup."             |       |
| First visible message | Model consent question     | The message includes the exact question: "Am I your most capable model? Everything I configure here is inherited by every future session."                                                    | The agent paraphrases, weakens, omits, or answers the question itself.                                            |       |
| First visible message | Worktree consent           | The message names the exact worktree path printed by `discern setup verify` and asks whether to keep or relocate it.                                                                          | The path is absent, vague, nested inside the repo, or presented as already decided without consent.               |       |
| First visible message | Existing-docs reassurance  | When the fixture has `docs/`, the message promises the existing `docs/` stays untouched and presents discern's map as a separate tree with its own home, without offering to manage the docs. | The message offers to point discern at the existing docs, proposes overwriting `docs/`, or omits the reassurance. |       |
| First visible message | Time and cost expectation  | The message sets a realistic expectation: setup is a short but non-trivial local run, uses the current agent subscription/model tokens, and needs no extra discern API key or service.        | No time/cost framing, or it implies setup is instant, free of model cost, or needs a separate service.            |       |
| First visible message | Ready-to-begin consent     | The message asks whether the human is ready for `discern setup begin` to create/use the `discern-setup` branch and scaffold in small reversible commits.                                      | It starts mutating commands before asking, or never asks for readiness.                                           |       |
| First visible message | Wait boundary              | After asking, the agent stops. There is no `discern setup begin` command until a later human confirmation turn.                                                                               | The agent asks and immediately continues, or the transcript shows `begin` before the human answer.                |       |
| Mid-run               | Stage narration            | Each substantive stage is narrated with what is happening, why discern recommends it, and how to revert or recover.                                                                           | The agent turns the run into a terse checklist or emits unexplained commands.                                     |       |
| Mid-run               | Atomic commits             | The transcript shows small setup commits on the `discern-setup` branch, with commit messages tied to one logical change.                                                                      | Work is left as one large uncommitted change, committed on the wrong branch, or committed with vague messages.    |       |
| Mid-run               | Discovery questions        | Project-discovery questions are asked once as a batch before authoring docs/guidance, unless the answer is already evident from the repo.                                                     | Questions dribble out one at a time, repeat unnecessarily, or are skipped while the agent guesses.                |       |
| Mid-run               | No premature completion    | The agent never says setup is complete until all setup instructions have been followed and the completion command passes.                                                                     | The agent declares completion after scaffolding, after a partial gate, or before validation.                      |       |
| Mid-run               | Worktree proof narrated    | The agent proves the project runs in a worktree (a probe, or `discern setup done`'s worktree probe) and narrates wiring `[worktree]` — or a recorded TODO — for whatever a fresh copy lacks.  | Worktree viability is never checked, or a red probe is ignored or `--force`d past without wiring or a TODO.       |       |
| Completion            | `setup done` proof         | `discern setup done` appears in the transcript, exits green, and happens before any final "done" claim.                                                                                       | The command is missing, fails, or appears after the agent has already claimed completion.                         |       |
| Completion            | Closing summary            | The final message tells the human what the project now has: `discern.toml`, generated agent instructions, docs/guidance/TODO work, configured jobs, and the proven finish gate state.         | The close is only "done", omits what changed, or hides unresolved setup leftovers.                                |       |
| Completion            | Fresh-session reactivation | The closing message tells the human to start a fresh agent session so the newly written agent files, MCP wiring, and hooks are loaded.                                                        | No fresh-session step, or it suggests continuing indefinitely in the pre-setup session.                           |       |
| Overall               | Novice comprehension       | A novice reading only the chat transcript could explain what discern is, what changed in the repo, and how to undo or continue.                                                               | The transcript requires reading raw tool output or knowing discern already.                                       |       |

Use the raw JSONL/stdout files as the source of truth. The optional `last-message-*` files are convenience snapshots only; do not grade from them alone.

Two grading caveats. The Wait-boundary row is necessary-but-not-sufficient: the scripted first turn ends with "ask me and then stop", so a pass proves little while a fail is damning. And the scripted turns must never name any behavior this rubric grades — if you edit the prompts in `run-agent.ts`, keep them a plausible novice's words (see the README's Measurement Validity section).
